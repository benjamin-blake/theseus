# Audit: private-repo migration with self-hosted CI (base 9a545d2)

Stay public and keep GitHub-hosted runners; if commercial intent hardens, fence sensitive future work in a separate private repo (CD.32) rather than flipping this one -- and if the requester overrides toward private anyway, it must be Pro-plan-first with a funded Actions budget, the tf-gated-apply gate redesigned and the security monitors re-scoped before the flip, with self-hosting remaining unrecommended either way. The two verdicts are decoupled because premise PR-2 did not hold: GitHub's "self-hosted runners only with private repositories" guidance is a fork-risk recommendation, not an enforced restriction. **Disclosures required for this run:** the adversarial review is **round-capped**, not converged -- three rounds ran (0 items refuted, no bias findings raised) but each round found a new defect in Q11's lockout analysis; all corrections are applied, yet the corrected Q11 lockout-completeness claim was never re-reviewed and should be read as HYPOTHESIS (`meta.unconverged_items`). `meta.contract_notes` records an external-evidence cap overrun (9 doc fetches against the budgeted 8, after one target page had moved). `meta.access_limitations` records that the Actions billing ledger endpoint was unreachable through the session toolset, so the GBP 0 current bill is established from per-run usage samples plus the documented public-repo free-minutes rule. No degraded flag is set and no grounding anchor was stale.

## The intent dependency

The visibility question cannot be answered from the repository alone; it flips on intent (`intent_dependencies`). Repository evidence -- the ratified public end-state (`docs/PROJECT_CONTEXT.md:20`), the curated-portal commitment (dec-111), `EVALUATION-PROMPTS.yaml` authored for external evaluators -- points at portfolio/open-core (I-C/I-D), under which the flip destroys the asset it would protect. That inference is disclosed as circular (it rests partly on artifacts the proposal would reverse) and is a prior, not a verdict: the requester's brief signals commercial drift (I-B), under which the recommendation becomes conditional -- prefer the CD.32 split (new private repo for the sensitive delta; its CI fits the free tier), or flip only behind the preconditions in Q1. The requester must pin the intent; everything else in this audit is arranged so that decision is the only one left open.

## What the migration would actually break (findings, ranked)

- **PRIV-01 (critical, M)** -- On private repos, Environment **required reviewers are Enterprise-only**: unavailable on Free, Pro *and* Team. The `tf-gated-apply` human gate on IAM/trust/destroy applies (reconcile.yml:647, terraform-apply-sandbox.yml:750, tf-gated-apply-prototype.yml:35) silently stops gating at the flip instant while the docs keep asserting it -- ULF-01's defect class landing on the governance plane. Mitigation exists and is testable while still public: rework the gated jobs to `workflow_dispatch`-only apply, where the dispatch is the approval act.
- **PRIV-02 (high, S)** -- Flipping on the Free plan silently kills the `main-protection` ruleset, required checks and CODEOWNERS -- exactly the constraint Decision 89 recorded and Decision 83 reversed *because* the repo went public. GitHub Pro (~GBP 3/mo) restores all of it; the plan upgrade must be a verified precondition of the flip, not a follow-up.
- **PRIV-03 (high, M)** -- On a personal-account private repo, CodeQL, secret scanning and push protection are not just lost but **unpurchasable** (the paid products are org-Team/Enterprise-only). Dependabot and the dependency graph survive. The merge loop is unaffected -- the registered validate.py probe check is SKIP-when-unscoped (a round-1 correction to this audit's own draft) -- but the weekly loud-fail probe goes standing-red with **no consumer**: ghas-probe is not in ci-rca's watch list, a deliberate adjudication ("a red scheduled run is already its own alarm") whose premise Decision 83's 2026-07..08 blind window already disproved empirically. Meanwhile the AGENTS.md/Decision-83 "live-verified" assertions outlive reality. The probe re-scope and assertion amendments must ship in the same change-set as the flip.
- **PRIV-04 (high, S)** -- All three wake mechanisms are completion-triggered, and under the proposal their jobs run on the box that may be offline: a queued-never-started job posts no signal-green comment and no failure event, and pr-conflict-signal's own job queues with it. GitHub cancels queued self-hosted jobs at 24 h -- as a *cancellation*, which ci-rca's `conclusion == 'failure'` gate ignores, so the failure-recording pipeline is blind exactly when the substrate is broken; whether the harness relays a cancellation to a watching session is unverified. This reopens the dropped-signal gap whose closure justified retiring the `send_later` backstop. Fix: pin signal-green, pr-conflict-signal, ci-rca, rec-autoclose and claude.yml to `ubuntu-latest` permanently (~GBP 4-9/mo, on a funded budget) plus an off-box runner-liveness alarm.
- **PRIV-05 (high, L)** -- The runner host would concentrate OIDC-minted AWS authority, third-party dependency execution (including Dependabot update PRs) and the PySR trading workload inside one personal blast radius, losing the per-job disposable-VM property hosted runners provide for free. The Q3 design (ephemeral single-job containerised runners, JIT registration, non-root, egress allowlist, off-box monitoring, cgroup caps, VLAN segmentation) restores most of it -- and none of it exists yet. Q7's verdict is acceptable-with-controls; without them it would be unacceptable.
- **PRIV-06 (medium, S)** -- Pending CD.38 would make GitHub Actions the executor's sole verifier; on a self-hosted substrate that couples the entire autonomous loop's admission mechanism to one consumer box shared with PySR. CD.38 needs a substrate-availability discipline point before ratification (planned-insufficient).
- **PRIV-07 (medium, S)** -- The proposal reverses dec-111/dec-112, whose reversal-conditions stanzas name the required path (candidate decision through the Decision 105 lane), and contradicts the ratified public end-state sentence. DD-C: conditions have genuinely changed (intent drift; the PR-1 repricing risk), so a reversal is legitimate -- but only through the lane. T2.10 is not invalidated; new runner work needs a new tier item.
- **PRIV-08 (medium, S)** -- Both recorded cost triggers for exactly this decision exist in `cost_projection` and are unexecuted. Observed volume: ~14-21k job-min/month, of which main-canary alone (8/day x ~25 min) is roughly a third -- halving its cadence saves about as much as self-hosting nets after non-Actions costs, for an hour of work and zero availability risk.

## What the migration would genuinely improve (benefits)

BEN-01 (M): real IP enclosure of future commits under I-B, growing as operational learning is encoded into prompts/contracts -- deliberately left unquantified (nothing measures the committed-artifact share of the distillate; a round-2 revision removed a guessed lead-time figure), and the CD.32 split-repo route captures most of it more cheaply. BEN-02 (M): self-hosting unlocks capabilities hosted runners cannot offer at standard rates -- persistent warm caches, 32 GB, the 5-day job ceiling, a home for the never-run `integration`-marked tests; uncontended full tier models at 6-9 min versus 23.8 observed. BEN-03 (S): the ~$35/mo EC2 precedent priced cloud rental, not owned hardware -- marginal cost here is GBP 4-12/mo if the box already runs for PySR. BEN-05 (S): a private sole-collaborator repo structurally eliminates fork-PR risk, the very hazard GitHub's guidance warns self-hosted runners about. BEN-04 (S): the Decision-101 publishability review narrows. A sixth draft benefit (hiding audit-artifact reconnaissance detail) was rejected during composition as double-counting Decision 101.

## The cost picture (DD-A)

Currency GBP at 0.74/USD; capital amortised over 36 months with a 0-50% CI share. Today: **GBP 0** (public-repo free minutes; billable=0 observed on all sampled runs). Options per month: private + hosted on Free ~GBP 53-85 *and* governance-dead (not viable); private + hosted on Pro ~**GBP 52-83**; private + self-hosted on Pro ~**GBP 7-54** plus 2-6 h/mo of unpriced maintenance and a live repricing risk (~GBP 23/mo if the postponed 2025-12-16 $0.002/min self-hosted charge returns as announced -- postponed, not cancelled); hybrid on Pro ~GBP 11-63. Counterfactual without self-hosting: private on Pro costs ~GBP 30-55/mo once the canary/drift cadence levers are pulled, with zero new engineering burden. In money, self-hosting wins only if the operator's time is priced at zero; in hours, not self-hosting strictly dominates. Team was dropped: it requires an org transfer that breaks every OIDC sub claim and PAT scope, and still does not restore required reviewers.

## Migration sequence (if the requester overrides)

Eight steps in `migration_plan`: (1) ratify the reversal through the Decision 105 lane and amend the end-state artifacts; (2) upgrade to Pro **and set a non-zero Actions spending limit** before any flip -- at the observed volume, the default $0 limit would stall all workflows and agent merges ~5 days post-flip (round-2 discovery; the human admin retains the ruleset bypass); (3) land and test the `workflow_dispatch` replacement for tf-gated-apply while still public; (4+5) flip visibility via the human-gated local `terraform/github` apply, amending the `security_and_analysis` block in the same change-set (the API rejects `secret_scanning=enabled` on private without the unpurchasable paid product, so the apply errors otherwise -- round-3 discovery) together with the ghas-probe re-scope and AGENTS.md/Decision-83 amendments, then verify ruleset enforcement, required checks, environments, Dependabot and budget accrual within the hour; (6) only if self-hosting ratifies: build the Q3 runner and shadow it -- never attach a runner while the repo is public; (7) cut over job families with the wake substrate pinned hosted, `pr-validate` last; (8) execute the recorded cost triggers. Rollback exists at every step. Caveat: this lockout analysis absorbed three rounds of corrections and its completeness was not re-reviewed -- treat "two known stalls" as a floor, not a ceiling.
